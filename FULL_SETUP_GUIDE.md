## 1. Схема работы системы

- **Сервер (FastAPI + Docker):** постоянно работает на вашем домашнем/удалённом сервере Ubuntu 24.04. Является единым источником правды (Single Source of Truth, SSOT).
- **База данных (`backlog.db`):** хранится в папке `./data` на сервере.
- **HLTB Microservice (Node.js + Docker):** работает во внутренней сети Docker и отвечает за получение времени прохождения игр с HowLongToBeat (порт 3000 наружу не публикуется).
- **Tailscale Funnel:** безопасно выставляет сервер наружу в интернет по HTTPS на порту `8443` (не конфликтуя с сайтом на порту `443`).
- **Android-клиент:** работает полностью автономно (Offline-first). При появлении интернета отправляет накопленные локальные действия из очереди `sync_queue` и забирает изменения с сервера.

## Шаг 1: Сборка Android-приложения (.apk)

Исходный код приложения находится в папке `android/`.

### Вариант А: Сборка через Android Studio (Рекомендуется)
1. Установите и запустите [Android Studio](https://developer.android.com/studio).
2. Выберите **File → Open...** и укажите папку:
   `c:\Users\admin\Desktop\GameRoom_x2\GameRoom-Unified\android`
3. Дождитесь завершения автоматической синхронизации Gradle (Gradle Sync).
4. В верхнем меню выберите:
   **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
5. После завершения сборки в правом нижнем углу появится уведомление со ссылкой **locate**.
   Готовый файл будет находиться по пути:
   `android/app/build/outputs/apk/debug/app-debug.apk`

### Вариант Б: Сборка через консоль (CLI)
Если у вас установлены JDK 17+ и Android SDK:
```bash
# В терминале Windows (PowerShell):
cd GameRoom-Unified\android
.\gradlew.bat assembleDebug

# В терминале Linux / macOS:
cd GameRoom-Unified/android
./gradlew assembleDebug
```
Готовый установочный файл появится в `app/build/outputs/apk/debug/app-debug.apk`.

### Установка приложения на смартфон:
1. Передайте файл `app-debug.apk` на телефон (через Telegram «Избранное», Google Диск, по проводу или через `adb install app-debug.apk`).
2. На телефоне откройте файл и разрешите установку из неизвестных источников.
3. Приложение **Game-Room** появится на рабочем столе смартфона.

## Шаг 2: Развёртывание сервера на Ubuntu Server 24.04

Серверная часть подготовлена к запуску в Docker-контейнере.

### 1. Перенос файлов на сервер
Склонируйте репозиторий или скопируйте папку `server/` на ваш сервер:
```bash
# Пример копирования через rsync с вашего ПК:
rsync -avz --exclude '__pycache__' --exclude '.git' ./GameRoom-Unified/server/ user@your-server-ip:~/gameroom/
```
Зайдите на сервер по SSH:
```bash
ssh user@your-server-ip
cd ~/gameroom
```

### 2. Запуск контейнеров через Docker Compose
В папке уже подготовлен автоматический скрипт запуска `deploy.sh`:
```bash
chmod +x deploy.sh
./deploy.sh
```

Что делает скрипт:
1. Создаёт папку `./data` с правильными правами доступа для non-root пользователя `gameroom` (UID 1000).
2. При наличии локального файла `backlog.db` копирует его в `./data/backlog.db`.
3. Создаёт конфигурационный файл `.env`.
4. Собирает Docker-образы и запускает контейнеры (`gameroom-web` и `hltb-service`) в фоновом режиме (`docker compose up -d --build`).

> **Важно:** HLTB-интеграция реализована через отдельный Node.js микросервис (`server/hltb-service/`). При выполнении сборки через Docker Compose он собирается и запускается автоматически. Устанавливать Node.js/npm на самом сервере вручную **не требуется**.

### 3. Проверка работы сервера
Выполните команды на сервере:
```bash
# Проверка статуса контейнеров (должны работать gameroom-web и hltb-service)
docker compose ps

# Проверка healthcheck эндпоинта
curl http://localhost:8080/api/health
```
Ответ должен быть: `{"status":"ok"}`.

Посмотреть статус контейнера и логи:
```bash
docker compose ps
docker compose logs -f
```

## Шаг 3: Настройка публичного доступа через Tailscale Funnel (Порт 8443)

На вашем сервере уже работает другой сайт через Tailscale Funnel на порту `443`.
Tailscale Funnel официально поддерживает публикацию на портах `443`, `8443` и `10000`. Мы используем порт **`8443`**.

Выполните на сервере две команды:

```bash
# 1. Привязываем внутренний порт контейнера 8080 к HTTPS-порту 8443 в Tailscale Serve:
sudo tailscale serve --bg --https=8443 http://127.0.0.1:8080

# 2. Включаем публичный доступ через интернет (Tailscale Funnel):
sudo tailscale funnel --bg 8443 on
```

Проверьте статус публикации:
```bash
tailscale funnel status
```
Вы увидите:
```text
https://<ваша-нода>.ts.net (ваш первый сайт) -> 127.0.0.1:...
https://<ваша-нода>.ts.net:8443 -> 127.0.0.1:8080 (Game-Room-Web)
```

Теперь ваш сервер доступен из любой точки мира через интернет по адресу:  
`https://<ваша-нода>.ts.net:8443`

## Шаг 4: Запуск и проверка Web-приложения на ПК

1. На ПК откройте браузер (Chrome, Edge, Firefox).
2. Введите адрес вашего сервера:
   - **Через интернет / в дороге:** `https://<ваша-нода>.ts.net:8443`
   - **Дома по локальной сети:** `http://<локальный-IP-сервера>:8080`
3. Откроется Cyber Comic веб-интерфейс **Game-Room**.
4. Перейдите во вкладку **«Настройки»** (иконка шестерёнки в левом меню).
5. Прокрутите вниз до блока **«📱 СИНХРОНИЗАЦИЯ С ANDROID (SYNC ENGINE)»**.
6. В строке `Секретный Sync Token для Android` нажмите кнопку **«📋 Копировать»**.  
   *(Этот токен сгенерирован сервером и защищает ваш API синхронизации)*.

## Шаг 5: Настройка и первичная синхронизация на Android

1. Откройте приложение **Game-Room** на смартфоне.
2. В нижнем меню перейдите в раздел **«Настройки»** (шестерёнка).
3. Прокрутите до блока **«СИНХРОНИЗАЦИЯ С СЕРВЕРОМ»**:
   - В поле **URL СЕРВЕРА** введите: `https://<ваша-нода>.ts.net:8443`
   - В поле **SYNC TOKEN** вставьте скопированный токен.
   - Включите переключатель **«Автоматическая синхронизация»**.
4. Нажмите кнопку **«Проверить связь»**:
   - Появится зелёный статус: `✅ Связь установлена! На сервере игр: N`.
5. Нажмите кнопку **«⚡ Первичная синхронизация (Initial Sync)»** и подтвердите слияние:
   - Приложение безопасно сопоставит игры телефона и сервера (по RAWG ID и названию с платформой), присвоит всем записям постоянные UUIDv4 и объединит базы без дубликатов.
   - Статус сменится на: `✅ Первичная синхронизация завершена!`.

## Повседневное использование и сценарии работы

### 1. Добавили игру на телефоне:
- Игра мгновенно сохраняется в локальной памяти телефона.
- Ей присваивается иммутабельный `uuid`, действие добавляется в очередь `sync_queue`.
- В шапке на кнопке синхронизации загорается оранжевый бейдж с цифрой `1`.
- Если включена автосинхронизация или вы нажали на кнопку со стрелочками в шапке — изменение моментально отправляется на сервер и появляется в веб-интерфейсе на ПК.

### 2. Изменили статус или часы на ПК:
- При следующем открытии Android-приложения (или нажатии кнопки синхронизации) клиент запрашивает дельту с момента последней синхронизации.
- Обновлённые часы, статус и заметки обновляются на смартфоне.

### 3. Офлайн-режим (в поездке или без интернета):
- Вы можете полноценно играть, добавлять игры, менять статусы, ставить оценки и удалять игры.
- Вся цепочка действий аккуратно схлопывается (компактизируется) в локальной очереди `sync_queue`.
- При подключении к Wi-Fi или мобильному интернету приложение автоматически отправит очередь на сервер в строгой последовательности `client_seq`.

### 4. Перенос из вишлиста в пройденные:
- При переносе игры из вишлиста в список игр её постоянный `uuid` сохраняется, а сервер меняет её статус на `playing` без создания копий.

## Обслуживание, бэкапы и обновление

### Резервное копирование базы данных:
Все данные хранятся в одном файле на сервере: `./data/backlog.db`.  
Создать горячую резервную копию базы данных SQLite можно одной командой без остановки сервера:
```bash
sqlite3 ./data/backlog.db ".backup ./data/backlog_backup_$(date +%Y%m%d_%H%M).db"
```

### Обновление сервера:
```bash
cd ~/gameroom
git pull
docker compose up -d --build
```
База данных в папке `./data` останется нетронутой.

*Примечание: Исходный код HLTB микросервиса (`server/hltb-service/`) также находится в репозитории и восстанавливается вместе с остальными файлами. Docker автоматически скачает необходимые Node-зависимости во время сборки образа, никаких дополнительных действий не требуется.*
