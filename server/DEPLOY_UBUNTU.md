# Руководство по развёртыванию Game-Room-Web на Ubuntu Server 24.04 LTS c Tailscale Funnel

В данном руководстве описано, как развернуть **Game-Room-Web** в Docker-контейнере на вашем сервере с Ubuntu Server 24.04.4 LTS и настроить доступ через интернет с помощью **Tailscale Funnel**, не нарушая работу уже запущенного сайта.

---

## 1. Архитектура сети и портов

На вашем сервере уже работает один Docker-контейнер, доступный через Tailscale Funnel (вероятно, на стандартном порту `443`).

Tailscale Funnel поддерживает публикацию в публичный интернет трёх портов:
- `443` (стандартный HTTPS) — занят вашим первым сайтом
- `8443` (альтернативный HTTPS) — **идеально подходит для Game-Room-Web**
- `10000` (альтернативный HTTPS)

### Схема взаимодействия:
```
[Android Смартфон / Браузер на ПК]
               │
               ▼ (HTTPS через Интернет)
https://<ваша-нода>.ts.net:8443
               │
               ▼ (Tailscale Funnel на Ubuntu 24.04)
        127.0.0.1:8080
               │
               ▼ (Docker порт)
[Docker Контейнер: gameroom-web] (FastAPI + Sync Engine)
               │
          ./data/backlog.db (Постоянное хранилище на диске)
```

## 2. Перенос проекта на сервер

Скопируйте папку `GameRoom-Unified/server` на ваш сервер (например, в `/opt/gameroom` или `~/gameroom`):

```bash
# С локального ПК через rsync или scp:
rsync -avz --exclude '__pycache__' --exclude '.git' ./GameRoom-Unified/server/ user@your-server-ip:~/gameroom/
```

Перейдите в директорию на сервере:
```bash
cd ~/gameroom
```

---

## 3. Настройка авторизации и запуск через Docker Compose

### Шаг 1: Установка зависимостей (для локальной генерации хэша)
```bash
pip install -r requirements.txt
```

### Шаг 2: Генерация Argon2id хэша пароля
Запустите интерактивную утилиту генерации безопасного Argon2id хэша:
```bash
python3 generate_hash.py
```
Утилита запросит ввод и подтверждение пароля и выведет готовую строку для вставки в `.env`.

### Шаг 3: Настройка файла `.env`
Создайте или отредактируйте файл `.env` в директории `server/`:
```bash
cp .env.example .env
nano .env
```
Укажите ваши персональные данные:
```env
# Имя пользователя для веб-входа
GAME_ROOM_WEB_USERNAME=ваш_логин

# Сгенерированный Argon2id хэш
GAME_ROOM_WEB_PASSWORD_HASH='$argon2id$v=19$m=65536,t=3,p=4$...'

# Опционально: фиксированный Sync Token для Android (или оставьте пустым для авто-генерации)
# GAMEROOM_SYNC_TOKEN=ваш_токен_синхронизации
```
> **Внимание:** Никогда не коммитьте файл `.env` с реальными учетными данными в Git!

### Шаг 4: Подготовка хранилища данных и запуск Docker
Для сохранения базы данных SQLite монтируется директория `./data`:

```bash
mkdir -p ./data
# Если уже есть существующая production база данных backlog.db, сохраните её в data/:
[ -f "backlog.db" ] && cp backlog.db ./data/backlog.db

# Запуск контейнера в фоновом режиме
docker compose up -d --build
```

### Шаг 2: Проверка работы контейнера
```bash
# Проверка статуса контейнера
docker compose ps

# Просмотр логов
docker compose logs -f

# Проверка healthcheck эндпоинта
curl http://localhost:8080/api/sync/status
```
Ответ должен содержать: `{"status":"ok","server_time":"...","total_games":...}`.

## 4. Настройка Tailscale Funnel (Порт 8443)

Так как порт `443` уже занят существующим сайтом, мы настраиваем проксирование входящих запросов на порт `8443`:

### Шаг 1: Настройка маршрутизации Tailscale Serve
Привязываем локальный порт `8080` (на котором отвечает контейнер) к HTTPS-порту `8443`:
```bash
sudo tailscale serve --bg --https=8443 http://127.0.0.1:8080
```

### Шаг 2: Включение Tailscale Funnel для порта 8443
Открываем доступ к порту `8443` из публичного интернета:
```bash
sudo tailscale funnel --bg 8443 on
```

### Шаг 3: Проверка статуса Funnel
```bash
tailscale funnel status
```
Вы увидите список активных публикаций:
```text
https://your-node.ts.net (ваш первый сайт) -> 127.0.0.1:...
https://your-node.ts.net:8443 -> 127.0.0.1:8080 (Game-Room-Web)
```

Теперь ваш сервер Game-Room доступен в интернете по адресу:
`https://<ваша-нода>.ts.net:8443`

## 5. Проверка Web Login и Android Sync
 
### 1. Проверка Web-авторизации
1. Откройте в браузере публичный адрес:
   `https://<ваша-нода>.ts.net:8443`
2. Неавторизованный пользователь увидит стилизованную страницу входа:
   - Логин
   - Пароль
   - Войти
3. Введите логин и пароль, настроенные в `.env`. После входа будет установлена защищенная HttpOnly/SameSite=Strict серверная сессия и откроется полнофункциональный интерфейс GameRoom.

### 2. Проверка Android Sync (APK v1.0.0)
Существующий выпущенный Android APK v1.0.0 работает без каких-либо изменений:
1. Откройте приложение **Game-Room** на Android-смартфоне.
2. В разделе **Настройки**:
   - **URL сервера:** `https://<ваша-нода>.ts.net:8443`
   - **Sync Token:** ваш существующий токен синхронизации.
3. Нажмите **«Проверить связь»** — сервер успешно авторизует запрос по существующему `Authorization: Bearer <sync_token>`.
4. Нажмите **«Синхронизировать»** для двусторонней синхронизации бэклога.

## 6. Резервное копирование и обслуживание

- **База данных:** хранится на хосте в файле `./data/backlog.db`.
- **Создание бэкапа базы данных:**
  ```bash
  # Сделать моментальный снимок базы данных SQLite:
  sqlite3 ./data/backlog.db ".backup ./data/backlog_backup_$(date +%Y%m%d).db"
  ```
- **Перезапуск контейнера:**
  ```bash
  docker compose restart
  ```
- **Обновление контейнера при изменениях кода:**
  ```bash
  docker compose up -d --build
  ```
