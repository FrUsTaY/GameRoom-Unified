## ✨ Ключевые возможности

- 📱 **Offline-First Android клиент:** полноценная работа без интернета, локальная очередь с компактизацией (`sync_queue`), монотонный `client_seq`.
- ⚡ **Двусторонняя синхронизация:** изменения на ПК мгновенно приходят на смартфон, а мобильные правки — на сервер.
- 🛡️ **Разрешение конфликтов LWW (Last-Write-Wins):** устранение перекоса часов через относительное время $\Delta t$, автоматическая доставка побеждающей версии проигравшему клиенту.
- 🗑️ **Надёжное удаление (Tombstones):** таблица `sync_tombstones`, защита от случайного воскрешения удалённых записей устаревшими обновлениями.
- 🔒 **Защита серверных метаданных:** частичные обновления с телефона никогда не затирают богатые метаданные RAWG (жанры, издатели, обложки, Metacritic).
- 🌐 **Работа в Tailscale Funnel:** сервер доступен через публичный HTTPS на порту `:8443`, работая параллельно с уже существующим сайтом на порту `:443`.
- 💾 **StopGame рейтинги:** полная поддержка фирменных SVG-плашек («Изумительно», «Похвально», «Проходняк», «Мусор»).
- ⏱️ **HowLongToBeat (HLTB) Интеграция:** автоматическое получение примерного времени прохождения через выделенный внутренний Node.js микросервис (без необходимости ручной установки Node.js на хосте).

## 🚀 Быстрый старт на Ubuntu Server 24.04 LTS

### 1. Перенос на сервер
Скопируйте директорию `server/` на ваш сервер:
```bash
rsync -avz --exclude '__pycache__' --exclude '.git' ./GameRoom-Unified/server/ user@your-server-ip:~/gameroom/
cd ~/gameroom
```

### 2. Запуск Docker контейнеров
```bash
chmod +x deploy.sh
./deploy.sh
```
Docker Compose автоматически соберёт два сервиса (`gameroom-web` и `hltb-service`), смонтирует постоянное хранилище `./data/backlog.db` и поднимет основной веб-сервер на порту `8080`. Отдельная установка Node.js на хосте не требуется!

### 3. Настройка Tailscale Funnel (Порт 8443)
Поскольку порт 443 уже занят вашим первым сайтом, открываем безопасный порт 8443:
```bash
# 1. Привязка порта контейнера к 8443
sudo tailscale serve --bg --https=8443 http://127.0.0.1:8080

# 2. Включение публичного доступа через интернет
sudo tailscale funnel --bg 8443 on

# 3. Проверка статуса
tailscale funnel status
```

Ваш сервер теперь доступен по адресу:  
`https://<ваша-нода>.ts.net:8443`

## 📱 Подключение Android-клиента

1. Откройте в браузере `https://<ваша-нода>.ts.net:8443/` и перейдите в **«Настройки»**.
2. В карточке **«СИНХРОНИЗАЦИЯ С ANDROID (SYNC ENGINE)»** нажмите **«📋 Копировать»** возле `Секретный Sync Token`.
3. Откройте приложение **Game-Room** на Android-смартфоне:
   - Откройте **Настройки** приложения.
   - Вставьте URL сервера: `https://<ваша-нода>.ts.net:8443`
   - Вставьте скопированный токен в поле **Sync Token**.
   - Включите **Автоматическая синхронизация**.
   - Нажмите **«Проверить связь»** (статус сменится на `✅ Связь установлена!`).
   - Нажмите **«⚡ Первичная синхронизация (Initial Sync)»** для объединения существующих баз.

## ⚙️ Правила разрешения конфликтов (Conflict Resolution)

| Ситуация | Правило разрешения | Описание |
| :--- | :--- | :--- |
| **Параллельное редактирование** | **LWW (Last-Write-Wins)** | Сервер рассчитывает относительную разницу времени $\Delta t$, устраняя погрешность часов клиента. Более свежее изменение побеждает. |
| **Проигравший клиент** | **Автоматическая сходимость** | Проигравший клиент получает актуальную победившую запись сервера и обновляет локальное состояние. |
| **Устаревшее удаление (Stale Delete)** | **Update побеждает Delete** | Если клиент удалил игру офлайн, а на сервере она была обновлена позже, удаление отклоняется, а запись возвращается клиенту. |
| **Устаревшее обновление (Stale Update)** | **Tombstone побеждает Update** | Если клиент редактировал игру, которая уже удалена на сервере, игра не воскрешается, а клиенту приходит команда на удаление. |
| **RAWG Метаданные (Категория B)** | **Защита от затирания** | Частичные обновления с мобильного клиента (часы, оценка, заметка) никогда не обнуляют серверные данные RAWG (жанры, разработчик, обложки). |
| **Перенос Wishlist → Games** | **Иммутабельный UUID** | UUID записи остаётся неизменным. Сервер меняет статус на `playing`, дубликат записи не создаётся. |
| **Офлайн-очередь на телефоне** | **Компактизация очереди** | Последовательные действия над одной игрой без интернета схлопываются в единое результирующее действие. |

Для проверки целостности всей системы в любой момент можно запустить автоматический сквозной прогон:

```bash

# 2. Модульные тесты серверного Sync API
cd server && python test_sync_api.py

# 3. Полные регрессионные тесты сервера
cd server && python test_suite.py

# 4. Модульные тесты Android движка синхронизации
cd android && node test_sync_engine.js
```
